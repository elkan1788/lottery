# 抽奖网页开发任务计划

## 1. 项目目标

构建一个基于 Next.js + PostgreSQL + Vercel 的在线抽奖系统，包含前台抽奖大屏和简单后台管理。前台重点还原设计稿氛围与跑马灯抽奖体验，后台满足奖品维护与中奖名单查看需求。

## 2. 需求边界确认

- 使用 Next.js 作为前端框架，并使用其服务端能力处理数据库访问
- 不单独部署传统后端服务
- 使用 PostgreSQL 存储业务数据
- 管理后台采用环境变量账号密码登录
- 抽奖参与仅需输入“花名”
- 支持同一花名多次抽奖
- 前台中奖名单实时展示最近中奖记录
- 中奖名单展示字段：花名、奖品名称、几等奖、中奖时间
- 时间统一按东八区展示，精确到分钟

## 3. 技术选型建议

- 框架：Next.js App Router
- 样式：Tailwind CSS
- ORM：Prisma
- 数据库：PostgreSQL
- 状态与交互：React Server Components + Client Components
- 表单校验：Zod
- 时间处理：dayjs
- 部署：Vercel

## 6. 数据表建议

### `lottery_prizes`

建议字段：

- `id`
- `name`
- `tier`
- `probability_weight`
- `stock`
- `image_url`
- `is_active`
- `created_at`
- `updated_at`

说明：

- `tier` 用于表示几等奖
- `probability_weight` 为中奖权重，不直接写概率百分比。抽奖时按所有候选奖品的权重总和做归一化随机，例如权重为 1/4/10 时，对应命中概率就是 1/15、4/15、10/15
- `stock` 表示可发放数量，抽奖时仅保留 `is_active = true` 且 `stock > 0` 的奖品
- `image_url` 直接存奖品图片地址，避免额外拆表
- 奖品无需单独描述字段，展示文案可直接由名称和等级承担

### `lottery_winner`

建议字段：

- `id`
- `nickname`
- `prize_name`
- `tier`
- `won_at`

说明：

- 中奖记录不再强关联奖品主表，只保留奖品名称和几等奖快照，避免奖品后续调整影响历史展示
- 时间展示时统一转东八区并格式化到分钟

## 7. 抽奖引擎规则建议

1. 仅从 `is_active = true` 且 `stock_remaining > 0` 的奖品中构建候选池
2. 使用 `probability_weight` 做加权随机
3. 抽中后通过事务完成：
   - 校验库存
   - 扣减库存
   - 写入中奖记录
4. 抽奖结果必须为真实奖品，不存在“谢谢参与”
5. 若全部奖品库存为空，可返回“活动已结束”状态

## 8. 风险点与注意事项

1. 不能将 PostgreSQL 直连暴露给浏览器端
2. 抽奖逻辑必须运行在服务端
3. 库存扣减必须使用事务，避免超发
4. 管理后台不能只做前端隐藏，必须做服务端鉴权
5. 跑马灯动画和真实中奖结果要解耦，先算结果，再驱动动画停止到目标奖品
6. 设计稿风格很强，开发时需要控制装饰和可读性的平衡

## 9. 建议开发顺序

1. 初始化项目与数据库
2. 完成 Prisma schema 与 migration
3. 先实现奖品管理、中奖名单和抽奖接口
4. 再实现前台页面与跑马灯动画
5. 最后做视觉细节、榜单联动和部署

## 10. 验收标准

- 可在首页输入花名并完成抽奖
- 抽奖为百分之百中奖
- 奖品按库存和权重正确发放
- 中奖后弹出结果浮层
- 最近中奖名单实时更新
- 名单展示花名、奖品名称、几等奖、中奖时间
- 后台可登录并维护奖品
- 项目可部署到 Vercel 并通过环境变量运行
